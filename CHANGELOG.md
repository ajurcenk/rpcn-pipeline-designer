# Change Log

All notable changes to the "rpcn-pipeline-designer" extension are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

- Environment variables in the settings: the new `redpandaConnect.env` setting holds variables as `"NAME": "value"` pairs for lint, Run, the live Bloblang errors and the Bloblang test panel. They win over the `redpandaConnect.envFile` file and over the environment VS Code was started with, so changing a `${NAME}` value no longer needs a separate file or a VS Code restart; the next command uses the new value and the live Bloblang errors are checked again at once. User, workspace and folder values merge by name, the most specific winning. Names must match `[A-Za-z_][A-Za-z0-9_]*` and values be strings; other entries are left out and named (not their values) in the output channel. The variables reach the binary in an owner-only env file in the extension's storage, passed after `envFile`'s; with the setting empty nothing changes. If that file can't be written, the command does not run and says why.
- Fixed: moving a file whose graph is hidden, with its editor open, onto a file whose graph is open (**Replace**) no longer marks the name hidden while that graph stays open. The open graph wins: the name is not hidden and its graph opens as usual next session. When the moved file had no editor open, the overwritten file's editor and graph close and the name keeps the moved file's Hide, as before.
- Fixed: renaming a config onto another config with **Replace** now brings its samples along. The overwritten config's `<name>.samples.json` goes to the OS trash (so it can be recovered) and the moved config's samples file takes its name, so the moved test panels show their own samples. Before, the overwritten config's samples stayed, the moved panels showed them, the moved config's samples file was left under its old name and "Samples weren't moved" was shown. With two files moved onto one name in one batch, the samples of the one whose content ends up there move to the name and the other's samples file goes to the trash. When the trash fails both files are left and "Samples weren't moved: <new name> already exists." is shown, as before; a rename onto a name with no config but a leftover samples file still keeps both and says so.
- Fixed: Bloblang test panels now count a config as having unsaved changes from the first edit after a save, and as saved again after an undo back to the saved text. Before, the first edit after a save was missed until a second one, so a rename or a close without saving could treat it as saved.
- Pipeline graph: the graph now follows a file through **Save As** to a new file, and an untitled config through its first save. The same panel moves to the new file, titled with its name and keeping its pan, zoom and collapsed groups, with the new file's editor as the one clicks select in; no second graph opens, and closing the old file's tab no longer closes it. A hidden file's Hide, and the memory that its graph was already shown this session, are copied to the new file (the old one keeps them), so the new file's graph does not open by itself either. VS Code reports no Save As, so it is recognised when a file created and saved in the last 2 s opens its tab just before another file's tab, and that tab closes within 1 s while the new one stays open; unsaved edits in the old file do not matter. Bloblang test panels still close with the old tab.
- Lint findings now survive edits elsewhere in the file. Before, the first edit after a save cleared every finding, so applying one Quick Fix cleared all the others and fixing several needed a save after each. Now an edit removes only the findings on the lines it changed (typing on a line, joining it to another or deleting it); the others move with their lines, keeping their Quick Fixes and their graph markers, until the next save replaces them all. An edit whose lines can't be told still clears them.
- Multi-root workspaces: `redpandaConnect.resourceFiles` and `redpandaConnect.envFile` can now be set per folder. Lint, Run, the live Bloblang errors and the Bloblang test panel read them for the config they are for: a relative value from that config's folder settings resolves against that folder (the same folder Run uses as its working directory); a value from the workspace or user settings resolves against the first folder, as before. A single-folder workspace is unchanged. `redpandaConnect.binaryPath` is still one per window.
- Path settings: on Linux and macOS, `redpandaConnect.binaryPath`, `resourceFiles` and `envFile` now expand a leading `~user` (`~alice/bin/redpanda-connect`, or just `~alice`) to that user's home directory, looked up with `getent passwd` on Linux and Directory Services on macOS (network accounts too). Before, `~user/…` was always a path relative to the workspace folder; it still is when there is no such user, so a file named `~draft.yaml` keeps working. `~`, `~/…`, absolute, relative and bare-name values are unchanged, and Windows keeps `~` only.
- Fixed: after an edit, a pipeline graph marker from YAML by Red Hat no longer lands on another node (for example one node off after a node is inserted above it) until Red Hat checks the file again. The graph now moves Red Hat's diagnostics with your edits until Red Hat republishes them, so the marker stays on its node without a blink; one whose text you replaced or deleted, and a YAML syntax error (which your edit may have fixed), is left out until then. Lint's markers then still cleared on the first edit.
- Fixed: fixing a YAML syntax error no longer makes a live Bloblang error's graph marker blink. Before, the marker disappeared for about 300 ms (the parse debounce) and came back; now the edit that makes the YAML parse again republishes the cached Bloblang errors at once, so the marker stays and the editor underline returns with it. While the YAML does not parse there are still no Bloblang underlines.
- Quick Fixes inside name-keyed maps: a misspelled field inside an entry of a map whose keys are free names (a `workflow` processor's `branches.<name>`, or any map with a value schema) now gets the same "Change to `<name>`" fix as anywhere else, preferred when it is the clear winner, and the same option-value fixes; the map's own keys are never changed. Gap completion is unchanged there.
- Bloblang completion on the left of an assignment: on an assignment target (`root.user.` before ` = …`, `let v` or `meta foo` before `=`) no methods or functions are offered, since neither fits there; after `root.` / `this.` the fields already written under that path still are. The right-hand side, `$` / `@` names and a line with no `=` after the cursor (a bare expression) are unchanged.
- Fixed: typing `rpcn` in a blank YAML file that is not yet a detected config now offers the whole-pipeline starter and the section snippets (any case, with or without the `-`), and accepting one replaces the whole typed word. Before, they were offered only on Ctrl+Space in a completely empty file. A blank file with any other word or content still gets no snippets, and detected files are unchanged.
- Fixed: renaming a config onto a file that already has a graph or test panels (**Replace** in the Explorer, or two renames in one batch landing on one name) now keeps the panels of the moved file, titled with the new name and showing its content, and its driving editor. Before, the overwritten file's panels stayed and the moved ones closed. Every test panel of the overwritten config closes, not only the one on the same processor; with two files moved onto one name, the one renamed last keeps its panels.
- Bloblang test panel: **From previous step** from a `generate` input. When a config's input is a single top-level `generate` input with a `mapping` (not a `broker`, not another input kind) and no input-level `processors`, the first processor of the same YAML document's `pipeline.processors`, a `mapping` or `mutation`, now offers **From previous step** ("New sample from input.generate", or from the input's `label`). It runs the generate mapping on one empty message (as its own test panel does) and saves the generated content and metadata as a new sample "from input.generate", selected and run. Later processors chain through it: with no selected sample before them, the generate mapping runs first, then each processor on the last output; a processor with its own selected sample still starts the chain there. A generate mapping that fails, reads `this` or deletes the message saves nothing and the error names it (`"input.generate" failed: …`). This is the one case where From previous step crosses a list boundary.
- **▷ Test mapping** for `generate` inputs: the `mapping` of a `generate` input (`input.generate`, or a `broker`'s `inputs` entry) now has the **▷ Test mapping** lens, and Test mapping at the cursor in it works. Its test panel is output only: no Input column and no samples. It runs once when it opens and shows one generated message, content and metadata; **Run** gives a fresh one, and with Run on change it re-runs when you edit the mapping (`count` and `interval` are ignored). The mapping runs as a `mapping` processor on one empty message, the message a real `generate` input's mapping starts from, so it gives the same output and the same errors as the input would (a syntax error, a failing line with Go to line, or `this` on the empty message), shown as for processors instead of being retried. One difference: `root = deleted()` shows "Message deleted" in the panel, while a real `generate` input produces nothing and never ends.
- Live Bloblang syntax errors in `generate` inputs: the `mapping` of a `generate` input (`input.generate`, or a `broker`'s `inputs` entry) is now parsed by your binary as you type, like a `mapping` / `mutation` processor. A syntax error is underlined at the binary's line and column and marks the input's graph node (the broker child's, inside a broker); fixing it clears both.
- Fixed: a live Bloblang error that the binary reports past a mapping's last character (for example `root.score = this.total *` typed as its last line), or on a blank or whitespace-only position after it, now marks its processor's graph node like any other Bloblang error. Before, it was underlined in the editor but no node got the marker. Selecting nodes with the cursor is unchanged.
- Fixed: the pipeline graph fits again when its panel is resized, for example when a test panel opens below it or a group divider is dragged, so its nodes no longer end up out of view. It fits once the size settles (about 150 ms after the last change), with the first fit's rule. Once you have panned or zoomed the graph it keeps your view instead, also after the view is recreated, until you use the new **Fit to view** button (bottom-right corner of the graph, after the graph in the Tab order), which fits the graph and lets later resizes refit again.
- Fixed: a graph whose YAML was closed no longer reopens it whenever its view reloads (which kept the closed file open for minutes); it shows its last graph instead (with whatever node status it still holds). A rename that is announced but never completes (it failed or was cancelled) no longer stops the file's graph and test panels from closing with its last tab, or a file later created at the new name from auto-opening its graph: it is forgotten after 30 s. A new test panel opened below the graph now makes sure focus is back in the YAML editor, and gives it back once more when the new group took it again.
- Bloblang test panel: **From previous step**. When the processor just before a mapping in the same list is a `mapping` or `mutation`, the sample controls end with **From previous step** ("New sample from <step>"). It runs the previous steps with your binary, from the nearest one that has a selected sample up to the one before this mapping, each on the last one's output, and saves the last output (content and metadata, non-string values as JSON text) as a new sample "from <step>", selected and run. A step that deletes the message or fails saves nothing and says so (`"<step>" deleted the message; no sample was saved.`, `"<step>" failed: <message>`), as does a chain with no sample (`"<step>" has no sample to run.`), a config with unsaved changes (`Save <file> first: samples are linked to the saved file.`) or an edit while the steps run (`The file changed while the previous steps ran; try again.`). Lists are never crossed (a `try:` or `switch` case's processors are their own), resources have no previous step, and the pipeline's input and processors of other kinds never run. New webview message `sampleFromPreviousRequested` and an optional `previousStep` in the snapshot.
- Corpus harness: Bloblang parity (R11). Every `mapping` / `mutation` processor of the `test/corpus` configs has samples in `<name>.samples.json` (the panel's samples format), and `npm run test:corpus` checks, on v4.100.0 and v4.112.0, that the test panel's run of each sample gives what the harness's own copy of the one-message `run` pipeline recorded in `<name>.bloblang/<ver>.json` (output content and metadata, deleted, the mapping error), and that the live parse's diagnostic for each mapping and for a syntax-broken variant of it is `blobl`'s message at its position. Any difference fails. A run the reference stopped must show the expected message (`blobl`'s parse error for a `Config lint error` it reports as one, else the recorded lint findings, checked on both binaries with a fixture whose mapping reads an unset `${…}`), and a `blobl` failure that is not a parse error must show `blobl`'s message; a real record altered in memory (content, deleted, error text, parse message, parse char) is shown to be reported. The run and parse orchestration moved from `bloblang.ts` into `bloblangRunner.ts`, with no `vscode` import, so the harness calls the real code; the panel's and the live parse's behaviour and messages are unchanged.
- Fixed: a `mapping` / `mutation` processor directly in a `try:`, `catch:` or `for_each:` list, at any depth (for example in a `branch`'s `try`), now gets live Bloblang syntax errors, the **▷ Test mapping** CodeLens and a test panel, like one in a `processors` list. Before, it was skipped.
- Bloblang test panel: keyboard and screen-reader support. The panel is named "Bloblang test panel: <title>" and its toolbar is the group "Test controls". The Content / Metadata tabs follow the tabs pattern: only the selected tab is a Tab stop, Left / Right switch tabs and Home / End go to the first / last. The output content can be focused, read and scrolled by keyboard. Esc anywhere in the panel returns focus to the YAML editor with its cursor unchanged (new webview message `focusEditorRequested`, the graph's); Esc in the rename field still only cancels the rename. One polite live region now announces every result and state once, and a rerun with the same outcome is not announced again ("Ran in 12 ms. added total, changed b", "Syntax error, mapping line 2: …", "Not run: …", …); the error cards, the status pill and the Output column are no longer live regions. The removed notice takes focus like the no-binary state. Every focusable element shows the `focusBorder` ring, and in high-contrast themes the badges, pills, cards, notices, columns, tabs and buttons have the contrast border.
- Bloblang test panel: placement, tabs and renames. Test panels now share one editor group of their own: with the file's graph open, a new group below the graph's (the graph's locked group never holds a test panel), else beside the YAML; focus stays in the YAML editor. A graph opened after a test panel goes into a new locked group above the test panels instead of joining them. Closing the file's last editor tab closes its test panels, as it closes its graph. Renaming the file, or its folder, keeps each panel open on its processor (unsaved edits too) under the new name, and renames `<old>.samples.json` to `<new>.samples.json` with it; when that file already exists both are left and "Samples weren't moved: <new name> already exists." is shown. Two optional snapshot fields, `fileName` and `samplesFile`.
- Bloblang test panel: the panel follows its processor. Lines typed above it, a processor inserted before it, a line retyped in one edit, or a labelled processor cut and pasted elsewhere no longer leave the panel on the wrong processor: after every edit each panel finds its processor again by where the edit moved it (else by its label), one panel per processor, and its title (`Bloblang: <label or path>`), its runs, its end-of-line hint and Test mapping follow. While the YAML is broken mid-edit nothing changes, and a file closed without saving puts the panels back on their saved processors when it opens again. A label typed or changed by hand renames the panel at once, and on save the samples of all of the file's panels move to their new labels or paths in one step; when samples already use that link nothing moves and "Couldn't move the samples to <link>: samples already use it." is shown. A deleted processor no longer leaves stale Bloblang: the panel stays open with "This processor was removed from <file>. Undo the change to bring it back.", runs nothing, clears its last result, and comes back (running once, with Run on change) when the processor does. One optional `removed` field in the snapshot.
- Bloblang test panel: **Add label** and the sample count. A panel whose processor has no label says "No label: samples are linked to this processor's position (`<path>`) and are lost if it moves." with **Add label**, which asks for a name (prefilled `<kind>_<N>`, checked against the binary's label rule, the document's labels and the labels the samples file already uses), writes `label: <name>` as the processor's first key (the file is not saved) and moves its samples from the path to the label, so they follow the processor when it moves; the panel's title becomes `Bloblang: <name>`. The **▷ Test mapping** CodeLens shows how many samples the mapping has (`▷ Test mapping · 3 samples`) and updates when a panel or anything else changes a `*.samples.json`. New webview message `addLabelRequested` and an optional `unlabelledPath` in the snapshot.
- Bloblang test panel: saved samples. The toolbar has a **Sample** picker with **New sample**, **Rename** and **Delete**. Each config's samples are saved in one JSON file beside it (`orders.yaml` → `orders.samples.json`, so they can be committed with the pipeline), linked to each mapping by its `label`, else its path. New sample saves the current input as "sample 1" (then adds empty "sample N"s); picking a sample makes it the input and runs it; Rename checks the name (1–100 characters, unique) inline; Delete asks first and selects the neighbour; edits to the selected sample are saved 300 ms after the last one, and a reopened panel comes back with its samples and runs the selected one. An edit of the file on disk or a save in VS Code reloads it; a file that can't be read is never overwritten and the panel says why ("The samples file can't be read: …") with the sample controls disabled. Untitled configs have no samples.
- Bloblang test panel: the no-binary state, after the prototype. Without a usable binary the panel keeps its header and shows "No Redpanda Connect binary" ("The test panel runs mappings with your own binary, so results match the version you deploy.") with **Install guide**, **Set path** and **Retry**, which run the same actions as the binary warning and the graph's empty state; it is announced once, nothing runs, and the input is kept. The host now sends every open test panel the binary's status (`binary`) whenever it changes and handles the three button messages. When the binary is fixed, each panel runs its current input once (whether Run on change is on or off) without reopening; a binary lost while a result shows hides it until that run.
- Bloblang test panel: errors and states, after the prototype. Each result has its own card and status pill: a syntax error ("✕ Syntax error · not run", "Mapping doesn't parse": the binary's `blobl` message and caret excerpt, the mapping's line and char and the file's line; a test run stopped by `Config lint error` is parsed again with `blobl` for that position, any other lint message, such as an unset `${VAR}`, is shown verbatim), a failure on the input ("✕ Mapping failed on this input", "Failed on mapping line N" with the file line, from `failed assignment (line N)`), an input the mapping can't read ("✕ Input not valid for this mapping"), a deleted message ("⊘ Message deleted · <N> ms", a dashed info card, "No output and no metadata.") and a run that could not happen ("✕ Not run", "The test could not run"). The error cards are alerts; a syntax error and a located failure offer **Go to line** (new handling of the `goToLine` message), which focuses the YAML editor with the cursor at that line's start, centred. Under an error card the last successful output since the panel opened stays, dimmed, without change marks. While a panel's latest result is a located failure, the failing line ends with ` ✕ fails on this input` in the editor (one decoration for all panels), cleared by the next other result, when the line leaves the processor, or when the panel closes.
- Bloblang test panel: metadata in and out, and what the mapping changed, after the prototype's layout. The panel now has an Input and an Output column with Content and Metadata tabs: the input's Metadata tab is a Key / Value table (**+ Add metadata**, **Remove**, a count of rows with a key; empty keys are not sent, the last of a repeated key wins), set on the test message by the `generate` input (`meta "<key>" = "<value>"`, `${…}` kept literal). The output shows its content pretty-printed when it is JSON, with the lines of added or changed top-level fields marked (tint and left bar), and its metadata in a read-only table with added and changed keys marked; the footer lists `+` / `~` / `−` tags, metadata keys as `@key`, or "No changes". The header's status pill reads "✓ Ran in <N> ms · <binary>". **Run on change** (on by default) runs 300 ms after a content, metadata or mapping edit; off, only **Run** runs. The content, metadata rows, tabs and the toggle survive a reload. The read-only Bloblang block is gone: the YAML editor beside the panel shows the mapping.
- Pipeline graph: live Bloblang syntax errors now mark their `mapping` / `mutation` processor's node (also inside a `switch` case or in `processor_resources`) like any other error: the error border and icon, rolled up to enclosing and collapsed groups, and the binary's message on hover beside the node's other messages. While the YAML does not parse the marker stays, and it stays when the YAML parses again. Before, a processor whose live error hid lint's duplicate showed no marker at all.
- Live Bloblang syntax errors: while you edit a detected config, every `mapping` / `mutation` processor whose Bloblang changed is parsed by your binary 300 ms after the last change (`blobl --file` on a temporary file in the extension's storage, stdin closed, with `redpandaConnect.envFile`, a 5 s limit, results cached by text, one parse per processor at a time). A syntax error is underlined at the binary's line and column, with its message, in its own collection (source `Bloblang`, Error), and clears when the mapping parses, the processor goes, the file closes or stops being a config, and while its YAML does not parse. Other failures, such as an unset `${VAR}`, show nothing and write one output-channel line per distinct message. No binary, no checking. On save, a lint finding inside a mapping with a live Bloblang error is hidden (the live error wins).
- Bloblang test panel (preview): a **▷ Test mapping** CodeLens on every `mapping` / `mutation` processor of a detected config, and **Redpanda Connect: Test mapping** for the processor at the cursor, open a panel per processor ("Bloblang: <label or path>") beside the editor without taking focus. Typed input runs once through the processor's current Bloblang with your binary (a one-message `run` of a temporary config, with the resource and env file settings and a 10 s limit) and the panel shows the output, the mapping's error, a deleted message, or the binary's message when the run fails. A second webview bundle, `dist/bloblang.js` / `.css`, with its own messages in `src/shared/bloblangProtocol.ts`.
- Fixed: pipeline graph interactions across features. Markers no longer go stale when a status update and a recreated view cross; Hide graph during a queued Show graph keeps the file hidden; Esc returns to the YAML editor in every state of the graph view (before the first layout, the empty states, the loading canvas, a first open on broken YAML), which is always one region named "Pipeline graph, read-only"; the live region announces the banner once per appearance (not for a recreated view, a schema drop and return, or a new parse message while it stays up), nor announces existing errors as new after a snapshot with no model; keyboard focus returns to the graph after it is drawn again; a closed graph posts nothing and stops its group lock (no spurious "Graph" error lines); renames reported as one batch (a chain or a swap) move every graph, Hide and driving editor to its own file; while the YAML does not parse, each node's accessible name ends with ", navigation unavailable while the YAML has errors".
- Pipeline graph: keyboard and screen-reader support. The graph is one Tab stop (the first node, or the one last focused, kept when the view is recreated); the arrows move between nodes (Right / Left siblings, Down into an expanded group or case, Up to its parent), Enter selects the node's YAML as a click does (`nodeActivated` with `via: 'keyboard'`), Space collapses or expands a group, Esc moves focus to the graph container and Esc again focuses the YAML editor without moving its cursor (new webview message `focusEditorRequested`). Focused nodes get the `focusBorder` ring. The container is named "Pipeline graph, read-only", each node is named "{role} {type}{, label}" plus a group's summary and state and its first problem, and one polite live region announces the invalid-YAML banner and each node that newly gets an error (the banner itself is no longer a live region). React Flow's own keyboard handling and descriptions are off. `npm run test:webview` also renders the graph in happy-dom (new dev dependency, 20.14.5) to drive the keys.
- Pipeline graph: auto-open and the Hide graph toggle. The first time an editor shows a detected config in a window session, its graph opens beside it (unless `redpandaConnect.autoOpenGraph` is `false`, the file is untitled, or you hid it), with focus left in the YAML; all graphs share one editor group, which is locked (best effort) so that other files open beside the YAML. **Show graph** (`$(type-hierarchy)`) and **Hide graph** (`$(eye-closed)`) appear in the editor title of a detected config and in the Command Palette, one at a time depending on whether the file's graph is open; no keybinding. Hide graph closes the graph and is remembered per file in the workspace state, across reloads, until Show graph; Show graph also marks the file as a Redpanda Connect config for the session, so it stays detected while you edit it. Closing the file's last tab closes its graph, and a rename moves the graph, its title and its Hide to the new name. New context key `redpandaConnect.graphOpenPaths`.
- Pipeline graph: empty states. Without a usable binary the panel draws no pipeline and shows "No Redpanda Connect binary. The graph needs it to read the schema." with **Install guide**, **Set path** and **Retry**, which run the same actions as the binary warning; a config with no pipeline sections shows "Nothing to draw yet. Add an `input`, `pipeline` or `output` section." When the binary is fixed or the schema arrives after the panel opened, every open graph draws without reopening or editing. The host now reports the real `hostStatus` (in the snapshot and whenever it changes) and sends no model while there is no schema.
- Pipeline graph: error and warning markers on nodes. Lint findings and YAML by Red Hat's diagnostics mark the node they fall in with a 2px error or warning border and its own icon (an error wins over a warning), and hovering the node lists its messages from the Problems panel, verbatim (up to 20). Severity rolls up to every enclosing group and `switch` case: an expanded group is marked for its own lines only, a collapsed group for everything it hides. Lint markers clear on the first edit after a save, as the findings do; while the YAML does not parse the last markers stay. The `nodeStatus` protocol message gains an optional `own` severity and `ownMessages`.
- Pipeline graph: two-way navigation. Moving the cursor in the YAML highlights the node under it in the graph (the innermost node; inside a collapsed group, the group's box), without moving focus or revealing the panel, and recomputed after every edit; while the YAML does not parse the highlight stays as it was. Clicking a node selects its YAML and now centres it in the editor the cursor was last moved in (with the file open in two editors, that one; else a visible editor for the file, else the first column), and clicking a group's header label selects the whole group. A recreated graph shows the current highlight.
- Pipeline graph: the graph follows edits live. Every change to a file with an open graph sends the complete model again; while the YAML does not parse, the graph keeps the last valid version under the banner "YAML has errors — showing last valid graph." with the parser's message, and clicking it selects the error in the editor. A file that does not parse when the graph opens shows the banner over an empty canvas. Updates keep the pan, zoom and collapsed groups, and the layout is deterministic, so whitespace, comments and values not shown in the graph move nothing.
- Corpus harness: `npm run test:corpus` also builds the pipeline graph of every `test/corpus` config with both pinned schemas and compares it with a recorded `test/corpus/<name>.graph/<ver>.json` (graph accuracy, no binary needed), and checks that every node's range resolves back to that node. `nodeAt` in the core maps a document offset to the innermost node containing it.
- Pipeline graph: groups are drawn as boxes holding their children (a header with a chevron, the component and its label), routes (`switch` cases, broker outputs, `try` / `catch` bodies, `workflow` branches) as captioned sub-boxes, and resources as standalone nodes. A group's chevron collapses it to one box with a count; the collapse state is kept across redraws. Colours come only from the VS Code theme. Bundles @vscode/codicons 0.0.46-24 (CC-BY-4.0 icons, MIT code), listed in NOTICE. `npm run test:webview` runs the graph view's layout tests (vitest), in CI too.
- Pipeline graph: the model now holds nested components (`switch` cases, `branch`, `try` / `catch`, `workflow` branches, broker and fallback outputs, batching processors, an input's and output's own processors, …) and `*_resources`, with which fields hold children read from the binary's schema. With no schema the graph is empty.
- Pipeline graph: **Show graph** opens a read-only graph beside a detected config (input, `pipeline.processors` and output, laid out with elkjs and drawn with @xyflow/react), one panel per file; clicking a node selects its YAML. Bundles React, react-dom, @xyflow/react and their dependencies (MIT, ISC, BSD-3-Clause) and elkjs (EPL-2.0), listed in NOTICE.
- Quick Fix **Fix all lint findings with a clear fix (N)**: applies the preferred fix of every lint finding in the file that has a clear one, as a single edit. Because the first edit after a save clears all findings, fixing them one by one needed a save after each fix.
- Binary resolution: `rpk connect` on `PATH`, then `redpanda-connect` on `PATH`, then `redpandaConnect.binaryPath` as a fallback; binaries older than v4.100.0 are rejected. The binary is resolved again when the setting changes.
- A warning with **Install guide**, **Set path** and **Retry** appears when no usable binary is found, once per change of state.
- Shared argument builder for lint and run (`--resources` from `redpandaConnect.resourceFiles` only, `--env-file` from `redpandaConnect.envFile`, `NO_COLOR=1`), used by lint on save and Run.
- Lint on save: findings from `lint --deprecated` appear as whole-line diagnostics (deprecated fields as warnings), hidden on lines YAML by Red Hat already flags (and lint's YAML syntax errors while Red Hat reports one), and cleared by the first edit.
