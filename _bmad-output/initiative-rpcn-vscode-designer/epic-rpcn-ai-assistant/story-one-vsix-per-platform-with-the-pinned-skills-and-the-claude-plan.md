## Intent

**Problem:** The assistant needs Anthropic's Agent SDK and its per-platform Claude Code binary. Today they're external to the bundle and missing from every VSIX. Shipping them inside our VSIX would redistribute Anthropic's code, which is all rights reserved under Anthropic's terms.

**Approach:**
- **One VSIX for every platform.** It carries the vendored `rpcn-skills` copy, never Anthropic's code.
- **The user installs the runtime on demand.** Install assistant runtime… asks for explicit agreement to Anthropic's terms, then:
  1. downloads exactly two tarballs from the npm registry over HTTPS: the SDK at its pinned version, and this platform's binary package;
  2. checks each one against the sha512 integrity pinned in `assets/agent-runtime.json`, generated from `package-lock.json` at build time;
  3. unpacks them into the extension's global storage.
- **The SDK and binary are loaded only from there,** at the pinned version.
- **Update assistant runtime** follows a new pin, and **Remove assistant runtime** deletes it.
- **The `skillsPath` override** points at a local `rpcn-skills` checkout instead of the bundled copy.

## Boundaries & Constraints

**Always:**
- **The VSIX** contains no `@anthropic-ai/claude-agent-sdk*` file, and CI packs exactly one VSIX (`vsce package --no-dependencies`). `check-vsix` fails a VSIX that holds any of them, or whose `package.json` has no exact SDK pin.
- **`assets/agent-runtime.json`** holds:
  - `sdkVersion`, the exact pin from `package.json`;
  - for the SDK package and each platform package: the tarball URL path, the version and the `integrity` (sha512), copied from `package-lock.json`.

  It's generated by a script, checked in CI by regenerating it and comparing, and read at run time.
- **The terms.** Install needs the user's explicit "Agree and install". The dialog links Anthropic's terms and names what will be downloaded. The agreement is remembered for that `sdkVersion` only. Escape installs nothing.
- **The download:**
  - HTTPS to the registry, `https://registry.npmjs.org` by default;
  - VS Code's proxy and CA settings (`http.proxy`, `http.proxyStrictSSL`) and `HTTPS_PROXY` / `NO_PROXY` / `NODE_EXTRA_CA_CERTS` are honoured;
  - a progress notification with Cancel;
  - each tarball verified before anything is unpacked;
  - unpacked to a temp folder in global storage, then swapped in by rename, so a failure or a cancel never leaves a half runtime;
  - `claude` keeps its executable bit;
  - tar entries are confined to the target folder: no absolute paths, no `..`, no links that point outside.
- **Loading.** The SDK and binary load only from `<globalStorage>/agent-runtime/<sdkVersion>/` (the binary passed as `pathToClaudeCodeExecutable`, the SDK imported by its `sdk.mjs` path). The installed version must equal `sdkVersion`. Nothing is ever resolved from an ancestor `node_modules` or `NODE_PATH`. The dev host and tests may use a development override pointing at the root `node_modules/`, honoured only in `ExtensionMode.Development` and Test.
- **States in the view:**
  - `runtimeMissing` ("The assistant needs Anthropic's Claude Agent SDK… Install assistant runtime…");
  - `runtimeInstalling` (progress);
  - `runtimeOutdated` (an installed version ≠ the pin: "Update assistant runtime…");
  - `runtimeFailed` (the reason, masked, with Retry);
  - `unavailable` (no binary package exists for this platform: "…isn't available for <platform> yet").

  The platform detection, musl included, is computed once per process.
- **Platforms.** Every platform the SDK ships a binary package for can install. Windows is still untested and out of scope (backlog story 1).
- **`redpandaConnect.assistant.skillsPath`** (application scope, empty by default):
  - only an absolute path, or one starting with `~`, that holds `.claude-plugin/plugin.json` and `skills/rpcn-design/SKILL.md`, `skills/rpcn-author/SKILL.md` and `skills/rpcn-test/SKILL.md`;
  - never equal to, inside, or containing the workspace folder, rechecked at each run start;
  - when valid, the plugin path and the shell and read rules use it, and the view shows "Skills: local copy";
  - otherwise `badSkillsPath`, with a text saying why (not absolute, not found, not a checkout, overlaps the workspace), and the state's `skills` field is `null`;
  - a value that isn't a string counts as unset;
  - the setting's description says that the folder's scripts run without asking.
- **A runtime that passes the view's check but that the host then can't load:**
  - the run's outcome is the matching state, not `error`;
  - the request is cleared;
  - no "run started" line is logged before the host accepts;
  - no error line is shown.
- **No automated test** calls a real model or reaches the real registry. Tests use a fake registry server and fake tarballs.

**Never:**
- Anthropic's code in the VSIX, or any per-platform VSIX.
- A download without the user's click and agreement.
- Unpacking an unverified tarball.
- Loading the SDK or binary from anywhere but the installed runtime folder (or the dev override in Development and Test).
- The `latest`-from-GitHub skills source (8.10).
- Publishing to a marketplace.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| First use | no runtime | `runtimeMissing` with Install assistant runtime…; nothing starts | none |
| Agree and install | the user agrees; the fake registry serves the two pinned tarballs | Progress, then the runtime is in global storage (`claude` executable); the state becomes `ready` (or the next access state) | none |
| Decline | Escape, or no agreement | Nothing downloaded; still `runtimeMissing` | none |
| Bad hash | the registry serves a tarball whose sha512 differs | Nothing unpacked; `runtimeFailed` "…didn't match the expected integrity" | logged, masked |
| Offline / proxy | the download fails, or the proxy refuses | `runtimeFailed` with the reason and Retry; no partial folder | none |
| Cancel | Cancel during download | No partial folder; `runtimeMissing` | none |
| Unsafe archive | a tar entry with `..`, an absolute path or an outside link | Refused; `runtimeFailed` | none |
| New pin | installed 0.3.329, the extension pins a newer version | `runtimeOutdated` with Update; Update installs the new one, then removes the old | as for install |
| Remove | Remove assistant runtime | The folder is deleted; `runtimeMissing` | none |
| Foreign copy | an SDK in `~/node_modules` or on `NODE_PATH`, no runtime installed | Still `runtimeMissing`; the foreign copy is never loaded | none |
| No binary for the platform | a platform the SDK has no package for | `unavailable` "isn't available for <platform> yet" | none |
| Binary vanishes | the runtime passes the view's check, then the host can't load it | The matching state, request cleared, no "run started" line, no error line | none |
| skillsPath | valid / invalid / overlapping the workspace / not a string | as the Always rules say | none |

## Decisions

- The extension never redistributes Anthropic's SDK or binary. There's one VSIX for all platforms, and the user installs the runtime on demand from VS Code. This replaces the earlier per-platform VSIXes (the user, 2026-11-25).
- The download goes straight to the npm registry over HTTPS by the extension itself, with no npm needed (the user, 2026-11-25).
- Integrity is checked against sha512 hashes pinned in the extension, generated from `package-lock.json` (the user, 2026-11-25).
- An explicit agreement to Anthropic's terms comes before installing, remembered per SDK version (the user, 2026-11-25).
- The runtime lives in the extension's global storage (the user, 2026-11-25).

## Implementation Notes

- **Reconciled:** `scripts/stage-agent-sdk.mjs` and its test, the CI per-target loop and `check-vsix`'s `--target` parts are gone; `setup-uv` stays. `platform.ts` keeps only the platform label and musl (once per process, `hostPlatform`); resolution moved to `runtime.ts`.
- **Runtime layout:** `<globalStorage>/agent-runtime/<sdkVersion>/node_modules/@anthropic-ai/{claude-agent-sdk,claude-agent-sdk-<platform>}/` plus a `runtime.json` marker written last in the temp folder (`.tmp-*`), then renamed in; other versions are removed after the swap. A folder without the marker never counts.
- **States:** `runtimeStatus` gives `unavailable` (no package in the manifest for the platform label, musl included), `missing`, `outdated` (another complete version folder), `installed`. The view adds `runtimeInstalling` / `runtimeFailed` from `AssistantRuntime`. Order: unavailable, runtime states, `badSkillsPath`, then the 8.1 access states.
- **The host:** `AssistantHostConfig.runtime` (`RuntimeFiles`) replaces `availability`; the error event's `runtimeMissing` replaces `unavailable`. The host checks the files at start, maps an SDK import failure and the SDK's "binary not found" throw to `runtimeMissing`.
- **Proxy, a finding:** VS Code's extension host patches `https.get` and, with `http.proxySupport: override` (the default), replaces a request's agent for non-loopback hosts, so a plain `https.get` with our own proxy agent goes direct (seen in the first suite run). `TunnelAgent` therefore does its `CONNECT` on a raw `net`/`tls` socket and `download` sends a proxied request through `http.ClientRequest` (with `_defaultAgent: https.globalAgent`), which the patch does not touch. With no proxy configured by us, `https.get` is used and VS Code's own proxy resolution and system certificates still apply.
- **Dev override:** the repository's `node_modules` at the pinned version, passed only in `ExtensionMode.Development` and Test; `RPCN_ASSISTANT_DEV_RUNTIME=0` turns it off in the dev host, and the suites turn it off with `setForTest({ devOverride: false })`.
- **Agreement:** `globalState['redpandaConnect.assistant.runtimeTermsAgreed']`, a list of SDK versions. Retry and a reinstall of the same version do not ask again; a new pin does.
- **Registry:** the manifest's `registry` (`https://registry.npmjs.org`); no setting was added for a mirror.
- **Verified on real tarballs (manual, no network):** the two real 0.3.329 tarballs from the local npm cache, served on loopback, install through `installRuntime` identical to npm's `node_modules` copy (`diff -rq` empty, binary byte-identical), and the binary prints `2.1.329 (Claude Code)`.
